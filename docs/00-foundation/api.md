# 00 基础设施 · API 文档

本模块只提供一个接口（健康检查），其余内容为**全站通用约定**，后续所有模块的
`api.md` 都默认遵循本文档，不再重复说明。

---

## 1. 通用约定

### 1.1 基础信息

| 项 | 值 |
|---|---|
| Base URL（本地） | `http://127.0.0.1:8000` |
| Base URL（生产） | `https://zouxp.xyz`（Nginx 反代到 `blog-backend:8000`） |
| API 前缀 | `/api/v1` |
| 编码 | UTF-8 |
| Content-Type | `application/json`（上传接口为 `multipart/form-data`） |

### 1.2 响应结构

所有业务接口（health 除外）返回统一包裹：

```json
{
  "code": 0,
  "message": "成功",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 表示成功；非 0 为错误码，见 1.4 |
| `message` | string | 提示文案，可直接展示给用户 |
| `data` | any \| 缺省 | 业务数据。**为 null 时该字段不出现**（不是 `"data": null`） |

> `data` 缺省这一点必须严格实现。前端代码里有 `if (res.data)` 这类判断，
> 如果返回 `null` 而不是缺省，某些分支会走进 else。

### 1.3 HTTP 状态码与业务码的关系

| 业务码范围 | HTTP 状态码 |
|---|---|
| `0` | 200 |
| `400-499` | 与业务码相同 |
| `500-599` | 与业务码相同 |
| `1000-3999` | **一律 400** |

也就是说：前端**不能只看 HTTP 状态码**，必须解 `code` 字段。

### 1.4 错误码

见 [00-foundation/design.md 第 6 节](./design.md#6-错误码表)。

### 1.5 鉴权

需要登录的接口带请求头：

```
Authorization: Bearer <access_token>
```

| 鉴权级别 | 含义 | 失败响应 |
|---|---|---|
| 无 | 不需要 token | — |
| 可选 | 带 token 则解析，不带也放行（如文章列表的 `is_liked`） | 忽略错误，当作游客 |
| 需登录 | 必须有效 token | 401 `{"code":401,"message":"请提供认证令牌"}` |
| 需管理员 | token 有效且 `role_id=1` | 401 或 403 |

### 1.6 时间格式

统一为 `YYYY-MM-DDTHH:MM:SSZ`：

```
2026-11-09T21:39:04Z
```

> ⚠️ 这里的 `Z` 是**字面量，不代表 UTC**。数据库存的是东八区本地时间，
> 序列化时直接拼 `Z`。这是照抄 Go 版本的既有行为，前端已按此解析。
> 修改为真正的 UTC 需要同步改前端，本轮不做。

### 1.7 分页

**两套字段，不要统一**：

| 使用场景 | 字段名 | 示例 |
|---|---|---|
| 文章列表 / 后台文章列表 | `page_size` | `{"list":[], "total":0, "page":1, "page_size":10}` |
| 后台用户列表 | `pageSize` | `{"list":[], "total":0, "page":1, "pageSize":10}` |

请求参数都是 `page` + `page_size`（查询串），页码从 1 开始。

### 1.8 字段命名

全部 `snake_case`。**不改名、不新增别名**，与 Go 版本逐字段一致。

### 1.9 空值处理

| 场景 | 返回 |
|---|---|
| 字符串字段为空 | `""`，不是 `null` |
| 关联对象不存在（如文章无分类） | `null` |
| 列表为空 | `[]`，不是 `null` |

## 3. 健康检查

### GET /api/v1/health

用于 Docker healthcheck、CI 部署后探活、Nginx upstream 检测。

**请求参数**：无

**响应**：注意这个接口**不使用统一响应结构**（照抄 Go 版本）

```json
{
  "status": "ok",
  "message": "blog-project API is running"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `ok` |
| `message` | string | 固定文案，保留 Go 版本的原文，不改 |

**状态码**：`200`

**说明**

- 这个接口只证明进程活着，**不检查 MySQL/Redis/MinIO 连通性**。
  依赖故障时接口仍返回 200，避免容器被 Docker 反复重启（对应 Go 版本的降级策略）。
- 若要做依赖探活，另开 `/api/v1/health/deep`，不复用此路径。
