### 提交前修掉的两个真缺陷

1. **Dockerfile 构建缓存注释与实际相反**
   原写法 `COPY pyproject.toml` → `COPY app` → `pip install .`，注释声称"改源码不用重装依赖"，
   实际上 COPY app 在安装之前，源码一变整层缓存失效，每次都重编译 asyncmy（2 分钟起）。
   改为：空占位包（只有 `app/__init__.py`）装依赖 → 拷真实源码 → `pip install --no-deps --force-reinstall .`
   实测 `pip wheel` 在只有空 `app/__init__.py` 时能正常构建，方案成立。

2. **日志目录权限**
   `USER app`（uid 1000）后 loguru 要写 `logs/`。镜像里预建并 `chown` 是必要条件，
   但更关键的是 compose 原本用 `./logs:/app/logs` bind mount —— Linux 上 Docker 以 root
   创建宿主目录，uid 1000 写不进去，启动直接 PermissionError。
   两套 compose 都改成命名卷 `blog_v2_logs`（会继承镜像内目录属主）。

### 踩到的坑（值得记住）

**Git 忽略规则里带斜杠的模式是相对 `.gitignore` 所在目录的。**
原规则 `configs/config.yaml` 只匹配仓库根的 `configs/config.yaml`，
文件移到 `backend/configs/config.yaml` 后不再被忽略，`git add -A` 把**含真实密码的配置**暂存了。
必须写成 `**/configs/config.yaml`。检查手段：`git check-ignore -v <path>`。

同类问题会影响所有多级目录项目，以后加忽略规则优先用 `**/` 前缀。
