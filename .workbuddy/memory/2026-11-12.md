### 提交前修掉的两个真缺陷

1. **Dockerfile 构建缓存注释与实际相反**
   原写法 `COPY pyproject.toml` → `COPY app` → `pip install .`，注释声称"改源码不用重装依赖"，
   实际上 COPY app 在安装之前，源码一变整层缓存失效，每次都重编译 asyncmy（2 分钟起）。
   改为：空占位包（只有 `app/__init__.py`）装依赖 → 拷真实源码 → `pip install --no-deps --force-reinstall .`
   实测 `pip wheel` 在只有空 `app/__init__.py` 时能正常构建，方案成立。

2. **日志目录权限**
   `USER app`（uid 1000）后 loguru 要写 `logs/`。镜像里预建并 `chown` 是必要条件，
   但更关键的是 compose 原本用 `./logs:/app/logs` bind mount —— Linux 上 Docker 以 root
   创建宿主目录，uid 1000 写不进去，启动直接 PermissionError。
   两套 compose 都改成命名卷 `blog_v2_logs`（会继承镜像内目录属主）。

### 踩到的坑（值得记住）

**Git 忽略规则里带斜杠的模式是相对 `.gitignore` 所在目录的。**
原规则 `configs/config.yaml` 只匹配仓库根的 `configs/config.yaml`，
文件移到 `backend/configs/config.yaml` 后不再被忽略，`git add -A` 把**含真实密码的配置**暂存了。
必须写成 `**/configs/config.yaml`。检查手段：`git check-ignore -v <path>`。

同类问题会影响所有多级目录项目，以后加忽略规则优先用 `**/` 前缀。

## 10:30 Swagger 无法带 token 的问题（commit ffa4aeb）

用户问能不能在 `/docs` 里直接测接口。实测发现：`/docs` 可开（mode=debug），63 个接口都在，
但 **OpenAPI 里没有 securityScheme** —— 鉴权用的是手写 `Header(alias="Authorization")`，
FastAPI 把它当普通 header 参数塞进每个接口的 parameters，Swagger 只给每接口一个输入框，
**没有全局 Authorize 按钮**，每测一个受保护接口都要重贴一遍 `Bearer xxx`。

修法（不影响运行时行为）：

```python
_bearer_scheme = HTTPBearer(auto_error=False, scheme_name="BearerAuth", description="...")

async def get_current_user(
    request: Request,
    authorization: str | None = Header(default=None, alias="Authorization", include_in_schema=False),
    _scheme: HTTPAuthorizationCredentials | None = Depends(_bearer_scheme),
) -> CurrentUser:
```

两个关键点：
1. `auto_error=False` —— 缺 token 时返回 None，不抛 FastAPI 默认的 403，
   401 文案仍由 `_extract_bearer` 决定，契约不变（测试全过证明没破）
2. `include_in_schema=False` —— 否则 parameters 里仍会重复出现 Authorization

`get_optional_user` 也加了 `include_in_schema=False`，但它**没挂** `_bearer_scheme`：
公开接口不需要锁图标，全局 Authorize 的 token 照样会被 Swagger 加到所有请求上。

验证结果：securitySchemes 只有 BearerAuth；`/user/info`、`/admin/users` 带 security，
`/articles`、`/auth/login` 不带；真实登录 → 带 token 访问两个受保护接口均 200；
不带 token 返回 401「请提供认证令牌」。172 测试通过。

### Swagger 自测的实际操作链（已写进根 README）

1. `GET /auth/image_captcha` → 拿 `captcha_id` 和 `base_64`
2. `base_64` 是 data URI，Swagger 只显示长字符串，**要整串粘到浏览器地址栏**才能看到图
3. `POST /auth/login` 填 account / password / captcha_key / captcha_code
4. 复制 `access_token` → 右上角 Authorize → 粘贴 → 之后所有接口通
5. 坑：登录响应**不含 refresh_token**（藏在 access token 的 `tid` claim 里），
   `/auth/refresh` 要传 access_token 本体，不是另一个 token
