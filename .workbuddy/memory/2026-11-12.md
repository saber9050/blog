### 提交前修掉的两个真缺陷

1. **Dockerfile 构建缓存注释与实际相反**
   原写法 `COPY pyproject.toml` → `COPY app` → `pip install .`，注释声称"改源码不用重装依赖"，
   实际上 COPY app 在安装之前，源码一变整层缓存失效，每次都重编译 asyncmy（2 分钟起）。
   改为：空占位包（只有 `app/__init__.py`）装依赖 → 拷真实源码 → `pip install --no-deps --force-reinstall .`
   实测 `pip wheel` 在只有空 `app/__init__.py` 时能正常构建，方案成立。

2. **日志目录权限**
   `USER app`（uid 1000）后 loguru 要写 `logs/`。镜像里预建并 `chown` 是必要条件，
   但更关键的是 compose 原本用 `./logs:/app/logs` bind mount —— Linux 上 Docker 以 root
   创建宿主目录，uid 1000 写不进去，启动直接 PermissionError。
   两套 compose 都改成命名卷 `blog_v2_logs`（会继承镜像内目录属主）。

### 踩到的坑（值得记住）

**Git 忽略规则里带斜杠的模式是相对 `.gitignore` 所在目录的。**
原规则 `configs/config.yaml` 只匹配仓库根的 `configs/config.yaml`，
文件移到 `backend/configs/config.yaml` 后不再被忽略，`git add -A` 把**含真实密码的配置**暂存了。
必须写成 `**/configs/config.yaml`。检查手段：`git check-ignore -v <path>`。

同类问题会影响所有多级目录项目，以后加忽略规则优先用 `**/` 前缀。

### 架构决策

- **token 存 localStorage**，不用 cookie（避免 CSRF）。代价是 SSR 读不到登录态，
  需要登录的页面一律关 SSR（`routeRules`，**页面级 definePageMeta 不生效**）。
- **刷新单飞**：后端 refresh 会轮换 tid，并发刷新会让后一个拿作废 token 去刷 → 直接踢下线。
  用模块级 Promise 做 single-flight。
- **导航账号区包 ClientOnly**：否则 SSR 渲染「登录」、CSR 渲染用户名，Vue 报 hydration mismatch。
- **评论区两级方向相反**：一级 DESC、二级 ASC，照后端契约。

### 踩的四个坑（都不是语法错误，是框架行为）

1. **`articles.vue` 与 `articles/` 目录并存** → 前者变成父路由，子页面没有
   `<NuxtPage>` 可渲染，`/admin/articles/new` 显示的是列表页。改 `articles/index.vue`。
2. **编辑器双栏塌陷**：`lg:flex-row` + 侧栏 `w-full shrink-0` 时，侧栏先吃掉 100%，
   主区（flex-1，basis 0）被压成竖缝。改用 main.css 里的原生媒体查询 `.editor-split`。
3. **后台布局重叠**：`fixed` 侧栏 + 内容区 `ml-52` 不生效。改 grid，列宽用内联 style
   （`grid-cols-[13rem_1fr]` 这类多值任意值实测不生成）。
4. **误判过一次**：以为 Tailwind 响应式整体失效，实际是 CSS 被打包成单行，
   `grep -c "@media"` 按行计数永远返回 1。判断编译产物要先看格式再下结论。
