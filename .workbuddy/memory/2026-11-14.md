## 「access 过期又让重新登录」续：不是 bug，是我把会话顶掉了

19:34 用户反馈又要求重新登录。日志还原：

```
19:17:31  400 code=1006 → POST /auth/refresh 200     会话正常续期
19:24:45  POST /auth/login 200                        ← 我的测试脚本登录（顶号）
19:30:00  GET /admin/articles 200                    用户的 access 还没到期
19:34:56  400 code=1006 → POST /auth/refresh 401「Refresh Token 无效」
```

关键区分：后端两种 401 文案 ——
- 「Refresh Token **已过期**」= Redis 没有 key
- 「Refresh Token **无效**」= key 存在但 `stored != claims.tid`，即被顶号

本项目是**单设备登录**：`refresh:{user_id}` 单 key，`_issue_tokens` 每次登录 SET 覆盖。
我为了拿测试 token 反复走真实登录接口，等于把用户的会话踢了。

**教训**：写自动化 / 调试脚本时不要用登录接口取 token，改用
`backend/scripts/mint_token.py` —— 从 Redis 读当前 tid 直接签 access，不碰会话。
验证：跑前跑后 `refresh:44` 的 tid 与 TTL 完全不变。

用户决定保持单设备设计，不改多设备。已确认刷新链路本身正常：
现造的过期 token 打开后台 → 400 → refresh 200 → 重放 200，页面停留正常，无需重新登录。

## 个人中心绑定邮箱「用不了」：前端漏传验证码

现象：点「绑定」没成功。查契约发现两个接口都是**必须带 6 位验证码**的：

| 接口 | 场景 | 必填字段 | 验证码发到 |
|---|---|---|---|
| `POST /user/add_email` | 从没绑过邮箱 | `new_email` + `captcha` | 新邮箱（purpose `add_email`） |
| `POST /user/email_ack` | 已绑定要换绑 | `password` + `captcha` + `new_email` | **当前邮箱**（purpose `reset_email`） |

而前端 `profile.vue` 只发 `{new_email}`，且界面只有一个邮箱输入框 —— 缺验证码输入、
缺发送按钮、换绑缺密码。后端返回 422「请求参数错误」，用户看到的就是「用不了」。
管理员账号恰好没绑邮箱（走 add_email），所以必然踩到。

补齐：邮箱区改成三行 ——（换绑时）当前密码 / 新邮箱 + 发送验证码 / 6 位验证码 + 提交，
发送按钮带 60 秒倒计时（和后端限流对齐）。说明文字点明「换绑时验证码发到当前邮箱」这个反直觉点。

**接口细节**（容易错的地方）：
- 换绑的验证码发**当前**邮箱，确认链接发**新**邮箱，两步各证明一端；
- `add_email` 在已有邮箱时返回 **403**（不是 400），前端按状态码分支要留意；
- `add_email` 直接生效不发确认邮件；`email_ack` 不改库，点链接（`GET /user/email?token=`）才写。

验证：未绑定态 UI 齐全；空提交被前端拦；发验证码 200 且 Redis 里出现
`captcha:email:<addr>:add_email`；错误验证码返回「验证码错误」（400，说明字段已齐全）；
mock 已绑定态 → 出现密码框、按钮变「申请换绑」、发码请求体是 `{email: 当前邮箱, purpose: reset_email}`。

## 个人中心改成「展示 + 点击修改」

原来一进页面就是一堆输入框（昵称/简介/邮箱/密码全摊开），像后台表单而不是个人主页。
改成三个区块各自「展示态 / 编辑态」：

| 区块 | 展示态 | 入口按钮 | 编辑态 |
|---|---|---|---|
| 基本资料 | `<dl>` 列出昵称/简介/账号 | 编辑 | 昵称、简介输入框 + 保存 |
| 邮箱 | 当前邮箱（未绑定显示灰字 + 一句用途说明） | 绑定邮箱 / 换绑 | 密码(换绑) + 新邮箱 + 验证码 + 提交 |
| 密码 | `********` + 注册时间 | 修改密码 | 三个密码框 + 确认修改 |

约定（三块统一）：
- header 右侧：展示态放入口按钮，编辑态**只放「取消」**（文字按钮）
- 主按钮（保存/绑定/确认修改）放在**表单底部**，紧跟在最后一个输入框后 ——
  填完往下看就是按钮，不用把视线拉回右上角
- 开关是三个独立的 `editingXxx` ref，互不影响
- 保存成功自动收起表单；提示文案放在区块底部，收起后仍可见
- 取消时把输入框回滚成服务端值，避免下次展开还留着废弃草稿
- 按钮样式抽成 `btnGhost` / `btnPrimary` / `btnText` 三个常量，同一串 class 不再抄六遍

验证：展示态三个区块 input 数量为 0；点编辑/换绑/修改密码分别只展开对应区块，
另两块保持只读；取消能收回；无 console 报错。顺带发现用户已经用新功能把邮箱绑成了
1223349392@qq.com（之前那版绑定是坏的，说明修复生效）。
